# eudoxys/wecc240 — package design (draft 1)

Status: draft, not yet agreed; written 2026-11-16 from the existing code
and READMEs to record current decisions and open questions. Decisions
below describe what the code does now unless marked *proposed*.

## Purpose

`wecc240` provides reduced-network PYPOWER models of the WECC
interconnection for power flow, OPF and quasi-steady time-series studies:

- static cases for 2011 (CAISO / Price and Goodin) and 2018 (NREL update);
- a 2020 time-series model with hourly node loads, distributed generation,
  solar and wind (in progress);
- planned: energy storage, load curtailment, and a 2025 model (see
  `TODO.md`).

Excluded: the county-level load models themselves (`eudoxys/loads`), EIA
data access (`eudoxys/eia`), and the solver and time-series engine
(`eudoxys/pypower`, `eudoxys/pypower_sim`).

Coverage: the WECC footprint (US West, British Columbia, Alberta, northern
Baja California), 243 buses; time series 2018–2022 hourly, UTC.

## Decisions settled

| # | Decision |
|---|---|
| 1 | Cases are PYPOWER case files (`.py`, one function returning a `dict`), generated by build scripts; never edited by hand. |
| 2 | The 2011 case is converted from the PSS/E revision 34 RAW file by `_psse.py` / `_case.py`, following MATPOWER `psse2mpc`. |
| 3 | The two HVDC lines (Pacific DC Intertie, Intermountain) are explicit `dcline` rows with 3.5% losses (`loss1`), replacing the RAW file's load/negative-load pairs; zero `dclinecost`. |
| 4 | 2018 generator costs are polynomial (`c2,c1,c0`) by generator type, fitted from NREL's `WECC240_2018_Generation_scheduling.xlsx` (`wecc240_gentypes.py`); `c0 = 0`. |
| 5 | 2018 branch `rateA` = first nonzero of `rateB`, `rateC`; branches loaded above 80% in the 2018 power flow get `rateA` raised to flow / 0.8. |
| 6 | 2018 voltages are brought under 1.1 pu with margin by generator `Vg` setpoints of 1.08 pu and shunt reactors at eight 500 kV buses (former issue #58). |
| 7 | Time-series nodes are identified by 6-character geohash, mapped to buses in `gis/wecc240.csv`. |
| 8 | US node loads are aggregated from county loads (`loads.aggregate`) using county-to-node contribution factors; Canadian nodes from BC Hydro and AESO data; Mexicali (`9mtzm4`) is a flat profile from the 2011 case. |
| 9 | Bus reactive load in time series is the bus's base-case `QD/PD` ratio times the hourly `PD`. |
| 10 | AESO 2017–2020 and 2020–2023 load series are reconciled by adding the 1 May 2020 offset to the later series. |
| 11 | Storage is scheduled for the CAISO duck curve: charge 09:00–15:00, discharge 15:00–21:00 (planned, Milestone 4). |
| 12 | Load curtailment has three regimes (none; level 0 at 10% of node load; level 1 at 15% of area load) triggered by load within 10% / 15% of import plus generation (planned, Milestone 5). |

## Conventions inherited

- From `eudoxys-package`: layout, packaging, `__version__`, logging,
  docstring style, testing tiers, CI, release as bare `YEAR.MONTH.SEQUENCE`.
- From `pypower` / `pypower_sim`: case format version 2, `idx_*` column
  indexes, `baseMVA = 100`, `PPData` inputs keyed by `BUS_I` and scaled by
  `1/baseMVA`.
- From `loads`: county FIPS keys and `elec_*_MW` column names.

## Contracts

| Object | Output |
|---|---|
| `wecc240_2011()` | PYPOWER case: 243 buses, `bus`, `gen`, `branch`, `dcline` (2 rows), `dclinecost`, `geodata`; no `gencost` (PF only) |
| `wecc240_2018()` | as 2011 plus `gencost` (polynomial, one row per generator); OPF and PF solve; all buses ≤ 1.087 pu and rated branches ≤ 80% in its PF |
| `wecc240_2020(adjustments)` | 2011/2018 case (open question 1) with `PD`, `QD` set to the peak hour of `data/wecc240_bus_PD.csv.gz`; each `{(table,column): scalar}` multiplies that column |

## Data sources and method

| Output | Primary source | Fallback / anchor |
|---|---|---|
| US node load | `loads.aggregate` county loads × county-to-node factors | EIA-930 BA demand (issue #1, closed) |
| BC node `c2c10y` | BC Hydro BA load and tie-line flows, 6.7% losses | — |
| Alberta node `c2u6xt` | AESO hourly load by area, CSD generation | 2020 Annual Market Statistics (check only) |
| Mexicali `9mtzm4` | 2011 case static values | none |
| Solar, wind, DG | NREL aggregated node production (SharePoint download) | — |
| Generator costs | NREL 2018 scheduling workbook | — |

Discrepancies are currently reported (printed), not forced to match.

## Outputs

`wecc240/wecc240_2020_{total,net,dg,solar,wind}.csv`: index `timestamp`
(UTC), one column per node geohash, MW. Not shipped with the package. Hour
convention (beginning vs ending) not yet documented (#14).

## Files and formats

Case files are Python; time series are CSV or gzip CSV with a `timestamp`
index. About 926 MB is tracked in the repository (#13); estimates of what a
pruned set would need are still to be made.

## Dependencies and gaps in sibling packages

| Need | Status |
|---|---|
| PF/OPF with DC lines | ✔ `_dcline.py` (local reimplementation; `pypower.toggle_dcline` fails with current numpy) |
| Time-series runs | ✔ `pypower_sim.PPSolver.run_timeseries` |
| County loads | ✔ `loads.aggregate` |
| Cached download of large inputs | none; would use `cache` (#13) |

## Known issues to handle

- PSS/E `YQ > 0` is capacitive and reduces `QD` (#7).
- `rateA` is 0 for every branch in the source RAW case.
- The AESO series discontinuity on 1 May 2020 (decision 10).
- The BC Hydro tie-line file was hand-edited to remove DST rows (#14).
- Mexicali has no hourly data (flat profile).
- `aggregate_total.py` leaves the first 24 rows out of its summary statistics without saying why (#8).

## Open questions

1. **Base of the 2020 model.** `README.md` says 2020 is built on the 2018
   model; `wecc240_2020.py` starts from `wecc240_2011()` (no generator
   costs, so no OPF) and its docstring cites Yuan et al. Options: use
   `wecc240_2018()`; keep 2011 and document why.
2. **Public API** (#12): re-export case functions, provide `PPModel`
   subclasses for every year, or keep renamed lazy dicts.
3. **Large data location** (#13): release assets + `cache`, separate data
   repository, Git LFS, or prune in place.
4. **CLI scope** (#5): one `run` verb for time series, or also `solve`,
   `build`, `export` verbs; which inputs it reads from an installed package.
5. **File naming** (#10): name time-series files by data year (2020) or by
   model year (2025)?
6. **Provenance of the 2020 model.** `README.md` says "commissioned by NRL
   in 2026"; is that NREL, NRL, or another sponsor? The 2025 model is
   attributed to LLNL. Record the funding/project references
   (`raw2py.py` cites REGROW, NREL-SUB-2025-10301).
7. **Legacy `PSSE/`** (#7): remove, or keep as an independent check of
   `_psse.py` after fixing the sign?
8. **`wecc240_case.py` vs `wecc240_map.py`**: which is used, and should the
   other be removed?
9. **Committed `docs/`** (#18): untrack it, given Pages builds in CI?
10. **Validation.** What independent reference data should the 2018 and
    2020 models be checked against (e.g. WECC reported peak 163.456 GW used
    in `viewer.py`, EIA-930 BA totals), and is there a pass/fail threshold?
    None is set yet.
